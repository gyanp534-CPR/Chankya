# Versioning Policy

## Snapshot Rule
- Each architecture version is immutable once approved.
- New changes create a new folder under `docs/architecture/versions/`.

## Naming Rule
- Use semantic document versions: `v0.1`, `v0.2`, `v1.0`.
- Pre-approval drafts can be named `vX.Y-draft`.

## Required Updates Per Version
1. Create new version folder from template.
2. Update `docs/architecture/README.md` current version pointer.
3. Add changelog entry.
4. Add/update ADRs for non-trivial decisions.
5. Add journal entry.

## Prohibited
- Editing historical approved version files except typo-only fixes with explicit changelog note.
- Recording major decisions only in chat without ADR or journal linkage.
